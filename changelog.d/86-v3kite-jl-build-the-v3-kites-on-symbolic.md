### Changed
- BREAKING: Works on the SymbolicAWEModels release whose model is the run. A run's positions, velocities, forces and settings are read with `run_value(sam, collection, i, quantity)` and written with `set_run_value!`, both re-exported by V3Kite. `V3KITE` has no `s.sys` any more: read the run through `s.sam`, and the structure through `s.sam.definition`.
- BREAKING: The helpers that read a run take the model: `calc_R_b_w`, `init_winch_torque!`, `force_to_torque`, `compute_kite_aoa`, `compute_wing_incidence`, `compute_bridle_euler`, `compute_bridle_pitch_angle`, `chord_ref_mid`, `span_mean_aoa`, `wing_station_chords`, `wing_twist_dist`, `differential_twist`, `aero_moment_z`, `update_sys_struct_from_data!`, `load_extra_points`, `relax_bridle!`, `plot_body_frame_local`, `plot_twist_dist` and `plot_replay`. The wing helpers take a wing index in place of a wing. `relax_bridle!(sam, config)` drops its structure argument.
- BREAKING: `set_steering!` and `set_depower!` set the tapes of a structure, or of a model's run once `init!` has built it. `tape_segment` returns the tape's index.
- BREAKING: `update_sys_struct_from_data!` sets the brake, steering and depower on the structure, which the next fresh `reinit!` takes into the run.
- BREAKING: `start_from_state!(sam, path)` drops its structure argument. `load_settled_struct` returns the structure placed in the settled pose and its transforms, `(sys, transforms)`, and takes no `set`; a model of it starts there at rest.
- BREAKING: Transforms and a run's settings are the model's, and placing and turning a kite is KiteGeometry's `place!` and `reposition!`. KiteGeometry's `load_authoring` replaces `load_sys_struct_from_yaml`, which V3Kite no longer exports; `load_v3_authoring` loads a geometry file with the kite settings' wing type, and `v3_model` builds a model with their aero mode and backend.
- BREAKING: A model takes its VSM settings: `build_settling_struct` returns `(sys, transforms, set, vsm_set)`, and `v3_vsm_settings(project, geometry_file)` gives a project's settings with its wing read from that aero geometry.
- BREAKING: Works with KiteUtils 0.14, where azimuth is anti-clockwise seen from above. `calc_azimuth_east` and a logged azimuth are positive towards the north: a kite due north reads +90°. `calc_turn_rate`'s frame-transport term is `χ̇ + φ̇·sin(β)` for that azimuth. The circle and zenith examples steer and plot with the new sign.
- BREAKING: V3Kite exports KiteGeometry's `SystemDefinition`, the structure type, in place of SymbolicAWEModels' old name `SystemStructure`. `calc_course` is a method of KiteUtils' `calc_course`.
- `create_v3_model` puts the kite's material on the structure before it builds the model, so the run is flown with it; `relax_bridle.jl` no longer applies it a second time.
- `set_damping_per_stiffness!` on a structure sets the segments' `damping_per_stiffness`, which the model turns into their damping; on a model after `init!` it sets the run's damping directly.
- `plot_body_frame_local` draws in a frame with the KCU as origin.
- The wing rows of the structure geometry files, and the beam geometry the Surfplan adapter writes, name a wing's dynamics `dynamics_type`, the column KiteGeometry reads, instead of `type`.
